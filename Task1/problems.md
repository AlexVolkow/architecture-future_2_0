## Основные проблемные области

1. **Нагрузка на DWH**
    - DWH выступает как единая точка отказа, поскольку все данные хранятся в устаревшем историческом хранилище (Microsoft SQL Server 2008).

2. **Отсутствие разделения данных**
    - Данные из различных областей, таких как финансы, медицина и ИИ, находятся в одной базе, что создает сложности при управлении.

3. **Устаревшая интеграционная шина**
    - Apache Camel требует значительных ресурсов для поддержки

4. **Технологическая устарелость**
    - Использование Microsoft SQL Server 2008 и PowerBuilder затрудняет поддержку и увеличивает затраты на масштабирование.

5. **Риски безопасности данных**
    - Недостаток централизованного контроля доступа приводит к уязвимостям и несоответствию требованиям законодательства.
    - Отсуствует аудит действий 
    - Отсуствует контроль за потоками данных. Контроль за разными категориями данных

6. **Несоответствие бизнес-логики**
    - Разные команды дублируют бизнес-логику при создании отчетов и обучении моделей, что приводит к расхождениям в данных.

## Приоритизация проблем (по методу MoSCoW)

### Must (обязательно)
- Внедрение Data Lake и разделение данных по областям.
- Создание портала для аналитики.
- Перенос бизнес-логики из DWH в отдельные сервисы.

### Should (желательно)
- Замена устаревшей интеграционной шины на более современное решение.
- Внедрение гибкой модели доступа и безопасности.
- Внедрение аудита и контроля за данными

### Could (можно сделать при наличии ресурсов)
- Замена PowerBuilder на более современную технологиию.
- Рассмотреть внедрение системы управляемых согласий в сервисе
- Создание единого поискового индекса

### Won’t (не делаем в этом году)
- Полный отказ от DWH — только постепенный вывод функциональности.
